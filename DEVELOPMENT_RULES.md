# DreamCloud Development Rules

## PRESERVE → ENHANCE → EXPAND

DreamCloud is in continuous enhancement mode.

Every development iteration must make the product **richer**, never smaller.

---

## The Core Rule

When modifying any screen or feature, follow this order:

1. **PRESERVE** — Keep all existing functionality intact
2. **ENHANCE** — Improve the visual design or UX of what already exists
3. **EXPAND** — Add new capability on top

The formula is always:

```
OLD FEATURE + NEW FEATURE
```

Never:

```
OLD FEATURE → DELETE → NEW FEATURE
```

---

## What You Must Never Do (Without Explicit Instruction)

- Remove pages or screens
- Remove cards or UI sections
- Remove tools or features
- Remove navigation paths
- Remove existing user journeys
- Replace a complete section that already provides value

---

## Pre-Modification Checklist

Before modifying any screen, complete this checklist:

1. List all existing functionality on the screen
2. Verify nothing from that list will disappear after your changes
3. Then build enhancements on top of the verified baseline

---

## Why This Rule Exists

DreamCloud is an accumulative product. Each iteration should compound value.

Features removed today are user trust lost tomorrow.

If a redesign eliminates a capability — even one that seems redundant — it creates gaps in the product that users relied on. The cost of removal is always higher than the cost of preserving and improving.

---

## Examples

### Correct approach

A screen has an "Araçlar & Arşiv" tools section.
A new "Dream Identity" hero section is added above it.
Both sections remain. The page becomes richer.

### Incorrect approach

A screen has an "Araçlar & Arşiv" tools section.
A new "Dream Identity" hero section is designed.
The tools section is removed to make room.
The page loses capability.

---

## Exceptions

A feature may be removed **only** when all of the following are true:

1. The user explicitly instructs removal by name
2. The feature being removed is confirmed to exist nowhere else in the product
3. The removal is acknowledged and confirmed before execution

---
